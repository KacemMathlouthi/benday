# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

[CONTRIBUTING.md](./CONTRIBUTING.md) is the human-facing guide and is accurate — read it for the contribution workflow, the changeset rules, and the test rationale. This file covers what is only visible after reading across several files.

## Commands

Bun workspaces driven by turbo. Run everything from the repo root.

```bash
bun install
bun run dev              # registry:build, then the docs site on :5173
bun run check            # lint and format (ultracite / oxlint + oxfmt)
bun run fix              # apply what check reports
bun run typecheck
bun run test             # the registry suite
bun run knip             # unused files, exports, dependencies
bun run build            # registry payloads, then every app
bun run registry:build   # regenerate apps/web/public/r/*.json only
```

CI runs `check`, `typecheck`, `test`, `knip`, `registry:build`, a `git diff --exit-code` on `apps/web/public/r`, and `build`.

A single test file or a single test — `bun test` has no turbo wrapper worth using here:

```bash
cd registry && bun test tests/bake.test.ts
cd registry && bun test -t "normalizes depth"
```

## The one structural rule

`registry/` is the product. It mirrors the tree the shadcn CLI writes into a consumer's project, which is why its internal imports are relative (`./benday/renderer`) and never aliased, and why only React may be imported. `apps/web` reaches the same source through the `@registry/*` alias instead of keeping a copy, so every example on the docs site is the code that ships.

`apps/web/public/r/*.json` is generated by `registry:build` and committed. Any change under `registry/` must be committed together with the regenerated payloads and a changeset, or CI fails on drift.

## Architecture

**The pipeline is image → `DotMap` → canvas.** `bake.ts` rasterizes a logo, separates ink from background (alpha when the source has soft pixels, otherwise a luminance mask estimated from the corners), derives a separate tone channel, runs an exact Euclidean distance transform so every dot carries its depth inside the shape, and grid-samples the result. The output is small and JSON-serializable on purpose: consumers can run the bake at build time and pass `dotMap` instead of `src`, skipping all of it on the client. `bake` is browser-only — it goes through a canvas.

**The renderer is imperative and outlives React.** `createRenderer(canvas, options)` owns the clock, the settle spring, and every cache; `renderer.update()` merges new options in. That is the reason `benday.tsx` is a thin shell — recreating the renderer on a prop change would restart the animation. The React component only owns the element, the bake, and the props.

**`dom.ts` holds every browser dependency** — resolving `currentColor` off computed style, watching theme and reduced-motion, and gating paint on an IntersectionObserver plus tab visibility. Keeping it in one file is what lets the rest of the runtime stay framework-agnostic.

**Presets are pure functions of one dot and the clock**, writing into a reused `out` object because they run once per dot per frame. Registering one in the `PRESETS` map is all that is needed: the docs table and the playground picker both read from it.

The renderer also consolidates an over-dense lattice when a cell would fall below 2 CSS pixels, and trades motion for optical weight below 32px — small marks are the case both the bake and the renderer are tuned around, so changes there should be checked at 16–20px, not just at 128px.

## The docs site is prerendered

`bun run build` in `apps/web` runs `vite build`, then an SSR build of `src/entry-server.tsx`, then `scripts/prerender.ts`, which writes one real HTML file per route plus `sitemap.xml`.

`src/lib/seo.ts` lists every page. **A new route must be added to `PAGES` there, and needs a matching `apps/web/content/<file>.md`.** There is no SPA fallback rewrite any more, so a route missing from `PAGES` is a genuine 404 on a direct hit, and a missing content file fails the prerender. `src/lib/head.ts` describes the head once and is used twice: serialized into the static HTML at build time, and applied in place on client navigation.

Every page is also served as markdown. `apps/web/content/*.md` holds the prose; `src/lib/feeds.ts` builds the markdown twin, `llms.txt` and the sitemap, substituting `{{presets}}` and `{{props}}` from `PRESETS` and `src/lib/api.ts`. The prerender writes them into `dist`, and a dev-only plugin in `vite.config.ts` serves the same builders, so those URLs are not 404s until you build. Vercel rewrites the page URL to its `.md` twin on `Accept: text/markdown`. That rewrite names the routes explicitly, so a new page belongs in `vercel.json` and its mirror too.

The authoritative deploy config is the root `vercel.json` (`apps/web/vercel.json` is a mirror and is not what Vercel reads).

## Conventions

- Any file using a React hook needs `"use client"`, or it throws when a Next.js server component imports it.
- Several files under `apps/web/src` are vendored from shadcn registries and are excluded from both oxlint and oxfmt — `components/ui/`, `components/ai-elements/`, `components/icons/`, `portal.tsx`, `theme-provider.tsx`, `hooks/use-scroll.ts`. Edits there are neither linted nor formatted, so match the surrounding style by hand.
- Commits use short conventional titles (`feat(web):`, `fix(registry):`, `docs:`). The body carries the reasoning the diff cannot show. **Do not add a `Co-Authored-By: Claude` trailer.**
